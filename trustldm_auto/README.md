# trustldm_auto: Automatic Evaluation Pipeline for LLDM Safety, Privacy, and Fairness

## Overview

trustldm_auto is an automatic evaluation framework for measuring the safety, privacy, and fairness robustness of large language models (LLMs). It implements an adaptive two-stage attack loop that automatically searches for “jailbreaks” by iteratively refining prompt perturbations using an attacker LLM.

> 🚨 **Safety reminder:** This project is intended for research and defensive evaluation. Do **not** use it to attack real users, production services, or generate harmful content outside of a controlled environment.

This benchmark has been accepted to **EMNLP 2026**. See the public paper:
[TrustLDM: Benchmarking Trustworthiness in Language Diffusion Models](https://arxiv.org/abs/2606.00023).

## Target Models

trustldm_auto supports evaluation of the following language diffusion models:

### Open-Source Models
- **LLaDA** (Language Latent Diffusion Model)
- **Dream** (Diffusion-based Language Model)

### Closed-Source Models
- **Mercury-Edit** (Proprietary language diffusion model, released April 1, 2026)

## Introduction

trustldm_auto performs automated jailbreak discovery using a **two-stage evaluation pipeline**:

1. **Attack prompt generation** (attacker LLM):
   - An attacker LLM generates pairs of `pre_context` + `post_context` that aim to push a target LLM into producing unsafe or biased completions.
   - Each pair is treated as an “adversarial prompt wrapper” around a fixed user query.

2. **Screening stage (fast judge):**
   - The target model is queried using multiple decoding strategies and generation lengths.
   - A fast judge assigns scores to each output to select the most promising candidates.

3. **Refinement stage (final judge):**
   - Top candidates are re-generated in full and re-scored using a more precise judge (often more conservative / specialized).
   - The best results are kept in a priority queue, and the attack model is guided using these high-scoring examples.

This pipeline is described in the paper (Introduction + Sections 7–8) as an efficient way to find jailbreaks with a small number of queries.

### Search Strategies

The evaluator supports three search settings:

- **Vanilla**: every decoding-method and generation-length candidate is fully generated by the target diffusion model and judged. It is simple but can be slow.
- **HS**: hierarchical search first performs short screening and then fully evaluates only the top candidates. This reduces full target-model generation, but adds judge calls and therefore increases judge query count, token usage, and API cost.
- **HS+SS**: search-space shrinking progressively focuses screening on promising decoding methods and generation lengths. It reduces the query, token, and cost overhead of HS; any time saving is a secondary benefit.

The default is `hs_ss`. Use `--search-strategy vanilla` or
`--search-strategy hs` for the corresponding ablations.

## Getting Started

### Recommended Python environment
- **Python 3.12**
- **PyTorch 2.7.1 + CUDA 12.8** for newer GPU architectures

The validated unified environment is `trustldm-d2f`. It supports LLaDA,
LLaDA-1.5, LLaDA-MoE, and Dream without maintaining separate model-specific
environments.

```bash
cd /path/to/Trustworthy_DLLM
conda create -n trustldm-d2f python=3.12 -y
conda activate trustldm-d2f
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r requirements-trustldm-d2f.txt
python -m pip install -e . --no-deps
```

The pinned versions are based on the validated server environment. Older
CUDA 11.8 setups may still require the legacy model-specific environments.

### Legacy CUDA 11.8 environments

For older GPU or CUDA 11.8 installations, use Python 3.10 and separate
environments because the historical LLaDA and Dream stacks require different
`transformers` and `tokenizers` versions:

```bash
# LLaDA family
conda create -n trustldm-auto-llada python=3.10 -y
conda activate trustldm-auto-llada
python -m pip install torch==2.1.0 torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118
python -m pip install -e .
python -m pip install transformers==4.43.2 tokenizers==0.19.1

# Dream: create a second environment, then use the same installation steps
# with transformers==4.47.1 and tokenizers==0.21.4.
```

### About Models & API keys
- For **local models** (e.g., LLaDA weights), you must update the paths in `trustldm_auto/config.py` or the `get_path()` function in `trustldm_auto/common.py` so they point to your local model directories (e.g., `/path/to/LLaDA-8B-Instruct`).
- For a local Mixtral attacker served through vLLM, set `MIXTRAL_LOCAL_BASE_URL` and optionally `MIXTRAL_LOCAL_MODEL_NAME`; the default endpoint is `http://127.0.0.1:8000/v1/chat/completions`.
- For **online (API) models**, ensure the required API keys are set as environment variables before running.
  - `TOGETHER_API_KEY` (Together/AWS models)
  - `QWEN_API_KEY` (Qwen judge)
  - `MERCURY_API_KEY` (Closed-source Mercury model)
  - `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GOOGLE_API_KEY` (if you use those backends)

## Run Evaluation

Start the evaluation by running `main.py` with the appropriate flags. The main command requires specifying the target model, dataset, perspective, and other parameters.

### An Example for fairness evaluation with Dream

```bash
python trustldm_auto/main.py \
  --target-model dream \
  --screening-topk 4 \
  --perspective fairness
```

### Another Example for safety evaluation with LLaDA

```bash
python trustldm_auto/main.py \
  --target-model llada \
  --dataset jbb \
  --screening-topk 4 \
  --perspective safety
```

### Example for safety evaluation with Mercury (closed-source)

```bash
export MERCURY_API_KEY="your_api_key_here"

python trustldm_auto/main.py \
  --target-model mercury \
  --dataset adv \
  --screening-topk 4 \
  --perspective safety
```

> ⚠️ **API Key Required**: Mercury is a closed-source model. You must set the `MERCURY_API_KEY` environment variable before running evaluations.

### Important args
- `--perspective`: `safety` / `privacy` / `fairness`
- `--target-model`: `llada`, `llada-1.5`, `llada_moe`, `dream`, `mercury`
- `--judge-model`: `qwen-plus`, `gcg`, `checkgt`, etc.
- `--screening-topk`: number of candidates kept after the screening stage.
- `--n-streams`: number of concurrent attack streams.
- `--n-iterations`: maximum number of iterative refinements.
- `--dataset`: `jbb` / `adv`, only in use for safety evaluation (specifies which dataset for the user query).

### Search ablations

Use `--search-strategy vanilla` for the full search, `--search-strategy hs`
for fixed-space hierarchical search, or the default `hs_ss` for hierarchical
search with progressive space shrinking.

### Reproducibility metadata

Every completed sample JSON stores a `summary.budget` object containing:

- `attack_query_count`: valid attacker outputs recorded by the attacker loop
- `judge_query_count`: judge calls, with `stage_breakdown` for screening/final
- `judge_input_tokens`, `judge_output_tokens`, and `judge_total_tokens`
- `judge_api_models`: API judge model names observed during the run

Local attack-model calls are not included in judge token totals. This makes the
query and token accounting auditable without counting locally deployed model
usage as API cost.

### Extending to another diffusion model

`generate_functions/generate_fastdllmv2.py` is kept as a minimal integration
example. A new generator should expose the same callable interface used by
`TargetLM`; model-specific code does not need to be part of the core pipeline.

## Files Usage

Relative files are placed in the `trustldm_auto` directory. Below is a brief description of the main files and their purposes:

| File | Purpose |
|------|---------|
| `trustldm_auto/main.py` | Orchestrates the full automatic evaluation loop (attack → screen → refine → log). |
| `trustldm_auto/conversers.py` | Implements the attacker/target model wrappers and generation logic. |
| `trustldm_auto/judges.py` | Implements judge models (fast screening judge vs. final judge). |
| `trustldm_auto/common.py` | Prompt templates, JSON parsing, and conversation initialization. |
| `trustldm_auto/system_prompts.py` | Contains system prompt templates for safety/privacy/fairness scenarios. |
| `trustldm_auto/loggers.py` | Saves results and experiment metadata to JSON. |
| `trustldm_auto/data.py` | Loads datasets used for each perspective. |
